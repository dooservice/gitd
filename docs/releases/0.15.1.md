gitd 0.15.1: merging without the whole history, a faster list, and a fix.

## Fixed

- Publishing again to a branch the same workspace published, without `--update`, moved the
  branch forward but asked GitHub for a second pull request, which it refused: the pull
  request now is the one already open, updated. A publish with no branch asked for the pull
  request of an empty branch: it now is of the branch published. 0.15.0 is affected; with
  `--update` and a branch named, it was not.

## Merging without the whole history

- `gitd update PATH --merge main` brings main's history only back to when the workspace was
  made: the commit both branches most likely share, which the workspace holds already. The
  whole history is brought only when git finds no shared commit in that much.

## A faster list

- `gitd list` describes the workspaces side by side, with one git process less for each.

## Upgrading

Nothing to do. The contract is unchanged. Clients: `pip install gitd-client==0.15.1`,
`npm install gitd-client@0.15.1`, `cargo add gitd-client@0.15.1`,
`go get github.com/dooservice/gitd/client@v0.15.1`.
