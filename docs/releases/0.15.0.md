gitd 0.15.0: gitd on a developer's machine.

What using gitd to work on gitd itself showed was missing, made part of it.

## One command to run it

- `gitd up` runs gitd for you: a configuration of your own where your system keeps them,
  gitd as your user service — systemd's user instance on Linux, launchd on macOS, the
  service on Windows — and the command line finding its socket without `GITD_SOCKET`.
  `gitd down` stops it, and keeps the configuration, pools and workspaces.
- When the GitHub CLI is signed in, gitd reads its token each time it starts, as
  `$GH_TOKEN`; it is never written to a file. Without it, `gitd up` says to run
  `gitd connect github`.
- Where gitd copies files because it cannot mount an overlay, `gitd up` says how to have
  workspaces made copy-on-write: the exact steps for gitd-mount, or the one line for reflink
  where the disk can clone without root. `gitd info` hints at it too.

## Working on a branch of your own

- `gitd prepare URL PATH --new-branch agents/fix` starts the workspace on a branch of its
  own; `gitd publish PATH`, with no branch, publishes the branch it is on.
- `gitd update PATH --merge main` takes main in: gitd brings it into the pool with the
  credential it keeps, and the workspace merges it with a merge commit. Nothing is forced, so
  the branch published before still moves forward. Conflicts stay marked in the files, to
  resolve and commit, and the call answers `REASON_CONFLICT`; a branch the repository has
  not answers `NOT_FOUND`.
- Publishing again to a branch the same workspace published moves it forward without
  `--update`: gitd records each publish outside the workspace, so nothing written in it can
  make gitd move a branch someone else published.
- `gitd list` lists the workspaces gitd made: repository, commit, branch, whether changed,
  and the branches published from each.

## For agents and platforms

- The contract grew: `PrepareRequest.new_branch`, `UpdateRequest.merge`, an empty
  `PublishRequest.branch`, `WorkspaceService.List`, and `REASON_CONFLICT`.
- MCP: `prepare_workspace` takes `new_branch`, `publish_branch` takes no branch, and two new
  tools, `merge_branch` and `list_workspaces`.
- The Python, TypeScript, Go and Rust clients have all of it.

## Upgrading

Nothing to do: the contract only grew, and `gitd serve` with no flags reads the same files as
before. Clients: `pip install gitd-client==0.15.0`, `npm install gitd-client@0.15.0`,
`cargo add gitd-client@0.15.0`, `go get github.com/dooservice/gitd/client@v0.15.0`.
