gitd 0.12.0: Windows.

## gitd on Windows

- `gitd-windows-amd64.exe` and `gitd-windows-arm64.exe`, for Windows 10 and 11 and Windows
  Server. It needs Git for Windows. See the [guide](../guides/windows.md).
- On a Dev Drive, or any other ReFS volume, workspaces are cloned from their template by
  blocks: the files share the template's blocks until written, as ReFS's reference counts
  show in CI. Elsewhere gitd copies the files, and `gitd info` says why it cannot clone.
- Windows clones file by file, where macOS clones a whole tree in one call. On CI's
  Windows Server 2025, a workspace of OCA/web took 0.5 to 0.9 s, about as long as a
  `git clone --depth 1` but with no download. Making it faster is the next release's work.
- `gitd service install|start|stop|status|uninstall` runs gitd as a Windows service,
  started with Windows and restarted when it fails. The local group `gitd` may reach the
  socket, read the pools and templates, and change the workspaces. The configuration,
  which holds credentials, stays SYSTEM's and the Administrators'.
- By default gitd keeps its socket and configuration in `C:\ProgramData\gitd`, and its
  state in `C:\ProgramData\gitd\state`.
- Files kept for gitd itself, such as connections and publishing settings, are readable
  by their owner, SYSTEM and Administrators only.
- git runs with long paths allowed, and workspaces and templates allow them too. Files keep
  the repository's line endings.

## Fixes found on the way, on every system

- A submodule's `.git` file and `core.worktree` are written with forward slashes, as git
  writes them.
- `gitd compare` takes a workspace by any absolute path, `C:\` included.
- When neither an overlay nor cloning can make workspaces, gitd says why for both.

## Upgrading

Nothing changes on Linux or macOS. The contract is unchanged. Clients:
`pip install gitd==0.12.0`, `npm install gitd-client@0.12.0`.
