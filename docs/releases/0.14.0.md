gitd 0.14.0: a client for Rust, and one name for every client.

## The Rust client

- `gitd-client` on crates.io, imported as `gitd`: Rust 2024, built with Cargo, from Rust
  1.85. `cargo add gitd-client`. See its [README](../../sdk/rust/README.md).
- The contract is generated by buf for prost and tonic and kept in the repository, so
  building it needs no `protoc`.
- It calls gitd on its socket, on Linux, macOS and Windows, where tokio has no Unix
  sockets and the client dials gitd's AF_UNIX socket itself; or on the network over TLS,
  with the key naming the caller's tenant. It reads the socket, the address and the key
  from the environment as the command line does.
- The calls the Python and TypeScript clients make, and the contract's own clients for the
  rest. A refusal carries gitd's reason, read as the other clients read it.
- CI builds it, lints it, tests it and calls a gitd from it, over the socket and over TLS,
  on Linux, macOS and Windows.

## One name for every client

The Python client is published as `gitd-client`, as the TypeScript and Rust ones are; it is
still imported as `gitd`. Up to 0.13.0 it was `gitd` on PyPI. The Go client is
`github.com/dooservice/gitd/client`.

## Upgrading

Nothing to do for gitd: the contract is unchanged. Python: `pip install gitd-client==0.14.0`
in place of `gitd`. Others: `npm install gitd-client@0.14.0`, `cargo add gitd-client@0.14.0`,
`go get github.com/dooservice/gitd/client@v0.14.0`.
